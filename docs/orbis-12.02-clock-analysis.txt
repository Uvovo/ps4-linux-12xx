============================================================
GPU USAGE REPORTING (for Linux implementation)
============================================================
On standard GCN/CIK hardware, GPU usage is derived from
GRBM_STATUS (mmio 0x8010). The register contains busy bits:

  Bit 31: GUI_ACTIVE (any graphics work active)
  Bit 30: TA_BUSY
  Bit 29: GDS_BUSY
  Bit 28: VGT_BUSY
  Bit 27: IA_BUSY
  Bit 26: SX_BUSY
  Bit 25: SPI_BUSY
  Bit 24: BCI_BUSY
  Bit 23: SC_BUSY
  Bit 22: PA_BUSY
  Bit 21: DB_BUSY
  Bit 20: CP_BUSY
  Bit 19: CB_BUSY
  ...

GPU utilization can be calculated by polling GUI_ACTIVE over
time intervals. The amdgpu driver already has this via
amdgpu_pm_info / gpu_busy_percent sysfs on cards with
PowerPlay. For Liverpool/Gladius without PowerPlay, a simple
GRBM_STATUS polling approach would work.

============================================================
GPU USAGE IMPLEMENTATION PLAN (for Linux)
============================================================
Current state: gpu_busy_percent sysfs returns -EOPNOTSUPP on
Liverpool/Gladius because kv_dpm_read_sensor() doesn't handle
AMDGPU_PP_SENSOR_GPU_LOAD.

Implementation approach:
  1. Add a periodic GRBM_STATUS poller (workqueue, ~100ms interval)
  2. Sample bit 31 (GUI_ACTIVE) each tick
  3. Calculate percentage over a sliding window
  4. Expose via AMDGPU_PP_SENSOR_GPU_LOAD in kv_dpm_read_sensor()

Register: GRBM_STATUS (mmio 0x8010 on CIK)
  Bit 31: GUI_ACTIVE - set when any GFX work is active
  
This is the same approach used by radeontop (userspace) and
the Orbis kernel's own telemetry system.

Alternative: Use RLC_GPU_CLOCK_COUNT_SPM and RLC_GPU_BUSY_COUNT
registers if available on Liverpool/Gladius. These give hardware-
level busy counters without needing software polling.
